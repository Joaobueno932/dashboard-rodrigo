Você receberá como insumos principais:

IMPORTANTE:

Os mockups NÃO representam o design final. Eles foram feitos apenas para definir:

- estrutura das telas;
- posição relativa dos elementos;
- quantidade de gráficos;
- organização das informações;
- filtros;

- botões;
- hierarquia de navegação.

O design deve ser profissionalizado, moderno e adequado a um dashboard corporativo ESG da FIEMS.

# Objetivo

Construir um dashboard web interativo para visualização dos indicadores ESG contidos na planilha da FIEMS.

O sistema deve:

- ler os dados reais da planilha;
- tratar e transformar os dados necessários;
- apresentar os indicadores em gráficos interativos;
- permitir filtros;
- possuir navegação entre Ambiental, Social e Governança;
- respeitar fielmente os mockups fornecidos;
- possuir interface moderna, corporativa, responsiva e profissional;
- funcionar completamente após a instalação das dependências;
- ser entregue como projeto completo em `.zip`.

O resultado esperado não é um protótipo.

É necessário entregar o SOFTWARE FUNCIONAL.

---

Antes de escrever código:

2. identifique as abas;

9. analise todos os mockups fornecidos;
10. monte internamente o mapa completo de navegação antes de iniciar o desenvolvimento.

Não presuma que todas as abas seguem exatamente a mesma estrutura.

Não presuma posições fixas de células sem verificar o arquivo.

Não altere os dados originais.

# Comportamento dos filtros

Os filtros devem utilizar somente valores existentes na planilha.

Não criar valores artificiais.

## CASA

Carregar dinamicamente as Casas existentes nos dados relevantes daquela tela.

Deve existir também uma opção equivalente a:

`Todas`

quando tecnicamente apropriado.

## ANO

Carregar dinamicamente os anos disponíveis para aquele indicador/tela.

Deve existir opção de visualização agregada quando isso fizer sentido.

Os filtros devem atualizar os gráficos imediatamente.

Os filtros da mesma tela devem funcionar de forma combinada.

# Tratamento dos dados

Criar uma camada clara entre:

1. leitura do Excel;
2. transformação;
3. dados utilizados pela interface.

Não espalhar lógica de parsing do Excel pelos componentes visuais.

Centralizar a transformação dos dados.

Quando possível, normalizar os dados para uma estrutura consistente.

Exemplo conceitual:

- dimensão;
- tema;
- indicador;
- código;
- Casa;
- Unidade;
- Ano;
- Mês;
- categoria;
- valor;
- unidade.

Não é obrigatório usar exatamente esse schema caso os dados exijam outra modelagem.

Analise primeiro.

---

# Importante sobre dados ausentes

A planilha possui valores em branco e possivelmente caracteres como:

`-`

Não transforme automaticamente isso em zero.

Considere como dado ausente quando o contexto indicar ausência de informação.

O sistema não deve:

- gerar `NaN`;
- gerar `undefined`;
- gerar `Infinity`;
- quebrar gráficos;
- apresentar valores falsos.

---

# Duplicidades

Não remova registros automaticamente apenas porque parecem duplicados.

Primeiro entenda a estrutura do indicador.

Caso existam registros perfeitamente duplicados e fique evidente que são inconsistências da fonte, trate de forma segura e documente a decisão.

Nunca altere a planilha original.

---

# Valores e unidades

- valores;

quando aplicável.
